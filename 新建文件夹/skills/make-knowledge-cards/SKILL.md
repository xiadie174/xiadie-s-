# Make Knowledge Cards

## 概述

把一段文本提炼成一组互不重复、单点聚焦的知识卡片，方便学习与复习。输入可以是用户粘贴的文本，也可以是本地 Markdown/TXT 文件；输出直接以 Markdown 呈现，默认 5～8 张卡片。

## 工作流程

### 1. 获取输入

- 用户直接粘贴文本：按粘贴内容处理。
- 用户提供本地 `.md` / `.txt` 文件路径：先完整读取文件内容再处理，不要凭文件名或印象猜测内容。
- 输入不明确（空文本、纯链接、截图）：说明需要什么，请用户粘贴文本或提供本地 Markdown/TXT 文件。

### 2. 通读并提取知识点

通读全文后，把文中承载信息的每个知识点单独列出，遵循以下边界：

- 只提取原文实际包含的信息，不补充、不推断、不延伸原文没有的事实、数据或结论。
- 跳过与知识无关的内容：客套话、问候、广告、与主题无关的闲笔、重复表述。
- 一张卡片只容纳一个知识点；不要把多个知识点硬塞进同一张卡片。
- 原样保留关键数字、专有名词、术语和结论，不擅自改写语义。

### 3. 筛选与去重

- 只保留真正重要的知识点：支撑文章主旨的核心概念、关键机制/步骤、可复用的结论或方法。删除次要细节、铺垫性描述和举例性注脚（除非该例子本身就是知识点）。
- 合并表达同一知识点的重复内容，去重后不得出现两张内容实质相同的卡片。
- 若两个知识点强相关但可拆开讲，拆成两张；若只是同一知识点的不同表述，合并。

### 4. 控制数量

- 目标 5～8 张。若知识点超过 8 个，保留最重要的 8 个，把相近知识点合并成更高一层的一个知识点，而不是删掉机制只留标题。
- 若全文信息量不足（知识点少于 5 个），不要强行凑数：如实输出更少的卡片（最少 1 张），并在输出末尾用一句话说明"原文信息有限，仅提炼出 N 个知识点"。
- 空输入或无实质内容的输入，不产出卡片，直接说明原因。

### 5. 组装与输出

为每个知识点生成一张卡片，固定采用以下结构：

```
## 卡片 N｜{标题}

**核心知识**
{1～3 句，准确概括该知识点}

**简明解释**
{2～4 句，用更通俗的语言讲清楚，可含类比或原文中的例子}

**例子或自测问题**
{一个具体例子，或一个能检验是否掌握的自测问题，两者至少其一}
```

规则：

- 标题：一句话点出知识点，不超过 20 字左右；优先沿用原文术语和表述，不要自创概念词。
- 核心知识：原文信息的准确浓缩，必须是原文可支撑的表述，关键数字、术语原样保留。
- 简明解释：帮助理解的通俗化说明；类比和例子不能引入原文之外的错误事实。
- 例子或自测问题：优先使用原文例子；没有原文例子时，可基于该知识点构造自测问题，但问题答案必须能从卡片内容推出，不能要求原文没有的信息。每张卡片给 1 个例子或问题即可，不要堆多个。
- 卡片之间用 `---` 分隔，按知识点的重要程度或文章逻辑排序。
- 直接在对话中输出全部卡片；若用户要求保存，再写成本地 `.md` 文件。

## 质量红线

- 不编造：卡片中每个事实、数字、结论都必须来自原文，宁缺毋滥。
- 不重复：任何两个知识点不得实质相同。
- 不堆砌：一张卡片只讲一个知识点，不做多知识点合并。
- 不硬凑：信息不足时减少数量并说明，不要用空话或常识填充。

## 不支持的范围

- 网页抓取：不访问 URL 抓取网页内容，需用户粘贴文本或提供本地文件。
- PDF 及其他格式：仅接受纯文本、Markdown（.md）、TXT（.txt）。
- Anki：不生成 Anki 导入格式，也不连接 Anki。
- 图形界面：不制作可视化卡片界面，只输出 Markdown 文本卡片。
