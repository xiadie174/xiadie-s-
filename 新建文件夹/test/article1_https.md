# HTTPS 是如何保护你的连接的

当你打开一个带锁的网站时，浏览器和服务器之间走的是 HTTPS 协议。很多人只知道"有锁就是安全"，但里面到底发生了什么？

## 明文 HTTP 的问题

HTTP 协议传输的内容是明文的。你在公共 Wi-Fi 上输入密码，如果路由器被坏人控制，这些数据会像明信片一样被直接看到。明文传输有两大风险：一是被窃听，二是被篡改——中间人可以把网页内容改掉，比如把下载链接换成病毒。

## HTTPS = HTTP + TLS

HTTPS 并不是一种全新的协议，它就是在 HTTP 外面套了一层 TLS（传输层安全协议）。TLS 负责两件事：加密数据，让窃听者看到的是乱码；校验身份，让浏览器确认对面真的是目标网站而不是假冒者。HTTP 负责原来的"发请求、收网页"功能，两者分工合作。

## 数字证书解决"你是谁"的问题

TLS 怎么确认服务器身份？靠数字证书。服务器把证书发给浏览器，证书里有域名、持有者信息和公钥。证书由 CA（证书颁发机构）签发，浏览器内置了受信任 CA 的根证书，所以能验证证书是不是真的。如果证书过期、域名对不上或不是受信任 CA 签的，浏览器会亮出警告。

## 非对称加密交换密钥，对称加密传输数据

加密分两类：对称加密（同一个密钥加密和解密）和非对称加密（公钥加密、私钥解密，或者反过来）。TLS 握手时先用非对称加密安全地交换一个会话密钥，之后传输数据都用这个会话密钥做对称加密。这样既安全又高效——非对称加密慢，只用来交换密钥；对称加密快，用来加密大量数据。

## 握手流程

一次 TLS 握手大致是：客户端说"你好，我支持这些加密算法"；服务器回应"好的，我们用这个算法"，并附上自己的证书；客户端验证证书后，用服务器公钥加密一个随机数发给服务器；双方用这个随机数各自算出会话密钥，握手完成，之后进入加密通信。

## 证书链与信任

CA 本身也有层级。根 CA 的证书内置在浏览器里，根 CA 给中间 CA 签发证书，中间 CA 再给网站签发证书，形成一条证书链。浏览器从网站证书往上追溯，只要链条完整且末端是受信任的根证书，就信任这枚证书。
